# 相机过场 · 设计

## Context

自动取景解决了"已解锁关卡看不见"的问题，代价是相机随进度拉远——实测岛屿直径 241px → 117px，且前 4 关每通一关变一次。这个变化本身是功能正确的（117px 在 iPad 上约 1.5cm，点得中），但因为是瞬间切换，观感上像"地图突然变小"。

已实测排除两条路：压紧现有布局会让岛屿一开始就变小、缩小幅度只从 51% 降到 37%；换成 3 行紧凑布局能让岛屿全程稳定，但整张地图必须一开始就装得下，锁定岛会全程可见——这与用户先前"保留往前探索的感觉"的选择冲突。

所以结论是：**保留取景逻辑与缩小幅度，把变化过程变成看得见的镜头运动**。

## Goals / Non-Goals

**Goals**

- 进地图时的缩放变化不再瞬变，读起来是镜头主动展开。
- 解锁动画里，相机拉远与新岛揭示的节奏对齐。
- 不改动岛屿坐标、取景求解与任何战斗/进度逻辑。

**Non-Goals**

- 不减少缩小幅度（用户已知并接受 241→117px）。
- 不加镜头旋转、跟随、缩放手势。
- 不做可跳过的开场动画——开场镜头期间岛屿仍然可以点。

## Decisions

### 1. 开场镜头：从 ×0.86 拉到最终取景

`frameProgressReveal(cleared)` 先把相机放到最终取景点但缩放乘 0.86（更贴近），再用 1000ms 拉到目标缩放。

**Why**：进地图时没有"上一个镜头"，无从做位置过渡；制造一个轻微的贴近起点，就能把"地图比我上次看到的小"翻译成"镜头退开让我看到更多"。0.86 是相对量——无论目标缩放是 1.0 还是 2.25，观感强度一致。

**Alternative rejected**：从地图一角飞入——位移太大，孩子会失去方位感。

### 2. 缓动用 inOutSine，不用 outQuad

先试了 `outQuad`（快起慢收），实测前 20% 时间就走完 45% 的位移，观感仍然是"猛地一缩再慢慢停"。`inOutSine` 起步和收尾都平滑，读起来是匀速的镜头推拉。

**Why**：这是"环境展开"而非"物体到位"，需要匀速感；`outQuad` 适合把某个元素送到位，不适合镜头。

### 3. 解锁镜头延后到 350ms，时长 900ms

原实现里 `playUnlock` 一开始就调 `frameProgress(…, true)`（0~700ms），镜头先动完，900ms 时新岛才上色——镜头与揭示脱节。

新时序：

| 时间 | 事件 |
|---|---|
| 0~520ms | 刚通关的岛弹跳（镜头不动，先看到"这座打完了"） |
| 350~1250ms | 相机缓缓拉远，把新解锁的岛纳入取景 |
| 500ms 起 | 新航线踏脚石逐颗弹出（与镜头拉远同时进行） |
| 900~1500ms | 新岛上色、插旗、地标长出、弹跳 |

**Why**：镜头退开与新航线铺出同步发生，观众的注意力被"路在延伸"带着走，缩放变化就成了背景动作而不是主体事件。

**Alternative rejected**：镜头先到位再揭示——实测是原实现的问题，揭示发生时镜头已经静止，缩放变化没有可依附的动作，反而更显眼。

### 4. 开场镜头期间不锁交互

镜头 tween 不阻断 `pickAt`，射线用的是每帧更新的相机矩阵，孩子在看镜头展开时仍然可以直接点岛。

**Why**：1 秒的开场不该变成"必须看完的动画"，尤其对坐不住的低龄玩家。

## Risks / Trade-offs

- **开场镜头让首次进地图多花 1 秒**：期间可交互，风险低；若真机反馈觉得拖沓，把 duration 从 1000 降到 700 即可，无需改结构。
- **解锁动画总时长变长**：从约 1.5s 变成约 1.7s（镜头 1250ms + 上色到 1500ms）。节奏更从容，但需真机确认孩子不会觉得等太久。
- **`Tweens.killAll()` 会中断镜头**：进关时会调用，镜头中断后停在中间状态；下一次进地图会重新取景，无副作用。
